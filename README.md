# wordle-solver

[![ci](https://github.com/notzenco/wordle-solver/actions/workflows/ci.yml/badge.svg)](https://github.com/notzenco/wordle-solver/actions/workflows/ci.yml)

A solver and benchmark for the five-letter word-guessing game, written in Go
with only the standard library. It implements five ways to choose a guess
(maximum information, fewest words expected to remain, best worst case, a
letter-frequency heuristic and a look-ahead planner) and plays each one
against all 2,315 answers in normal and Hard Mode. It then reports how many
guesses each needs, how often it fails and what it costs to run. The best of
them averages about 3.5 guesses and never fails in normal mode. Every
number in the [analysis](docs/analysis.md) is regenerated by one command.
The solver also helps you play, and it includes a documented
[model of human play](docs/human-model.md) that is compared with real
results people reported.

## How it chooses a guess

Each guess earns one of 3⁵ = 243 colour patterns: green for a letter in the
right place, yellow for a letter elsewhere in the answer, grey otherwise.
The solver keeps the *candidates*, the answer words that fit every pattern
so far. A good next guess is one whose possible patterns divide the
candidates into many small groups, because then any outcome leaves little
to choose from.

The strategies differ in how they measure that split:

- `entropy`: the most information, in bits, over the patterns;
- `expected`: the fewest candidates expected to remain;
- `minimax`: the smallest worst-case group;
- `freq`: no splitting at all, just the fitting word made of the most
  common letters;
- `planner`: looks ahead and guarantees as many answers as possible within
  the next three guesses.

The first three score every allowed guess, including words that can't be
the answer but split the candidates well, which is how they escape families
like _OUND. In Hard Mode, every guess must reuse the letters already
revealed, so that escape disappears. A precomputed 2,315 × 2,315 table of
patterns makes each split an array lookup, so a full comparison runs in a
few seconds.

```sh

```

## Install

Download the archive for your system from the
[latest release](https://github.com/notzenco/wordle-solver/releases/latest)
(macOS, Linux and Windows, on Intel/AMD and ARM), unpack it and put
`wordle-solver` (or `wordle-solver.exe`) somewhere on your `PATH`.
`checksums.txt` lists each archive's SHA-256. The binaries are not signed:
on macOS, clear the download quarantine with
`xattr -d com.apple.quarantine wordle-solver`; on Windows, SmartScreen may
ask you to confirm the first run.

Or build from source with Go:

```sh
go install github.com/notzenco/wordle-solver/cmd/wordle-solver@latest
```

From a checkout, use `go install ./cmd/wordle-solver`. `wordle-solver
version` prints your version, and `wordle-solver update` replaces the binary
with the latest release after checking it against `checksums.txt` (a build
from a checkout needs `-force`).

## Usage

```sh
wordle-solver help                    # every command; 'help COMMAND' or 'COMMAND --help' for its options
wordle-solver play                    # play today's puzzle yourself: coloured tiles, no hints
wordle-solver play --random           # practise on a random answer (offline, not saved)
wordle-solver assist                  # type your own words; it fills in the colours and suggests the next
wordle-solver assist --manual         # the same while playing on the website: you type the colours too
wordle-solver                         # solve today's puzzle by itself with the human-like player
wordle-solver auto --by solver        # ... with the entropy strategy
wordle-solver auto --by model --model omlx/clef-flash-4bit   # ... with a model, through the eval harness
wordle-solver auto --date 2026-11-12  # another day's puzzle (or --id N, or --from N --to M)
wordle-solver sim crazy               # watch the human-like player solve a given answer
wordle-solver bench --strategy all    # compare the five strategies
wordle-solver stats                   # the human-like player's record; --mine for your own games
wordle-solver sync                    # cache every past answer (a few minutes)
wordle-solver clean                   # delete the saved profile, games and answers
wordle-solver settings                # saved defaults and where each value comes from
```

### Approaches

`auto` and `assist` take `--by`:

| Approach | Chooses guesses with | Notes |
| --- | --- | --- |
| `human` (default) | the human-like player model | habits and occasional slips; each run draws a new seed, printed so `--seed` replays it |
| `solver` | the entropy strategy | the best in the benchmark |
| `model` | a model given with `--model`, through the [eval harness](docs/eval.md) | chat models reply with a word; decision models such as Clef choose from up to 64 words that fit |

Every approach chooses from the colours alone. The answer is looked up only
to score guesses, and a model never sees it. Only the human-like player's
games are saved, to its own history; games you play with `play` go into a
separate history shown by `stats --mine`. In a terminal, guesses show as
coloured tiles; `NO_COLOR=1` or a pipe gives letters and emoji instead.

Each command accepts only its own options, with one or two dashes, before or
after its arguments. The solving commands (`auto`, `assist`, `sim`, `bench`)
share these:

| Option | Effect |
| --- | --- |
| `--hard` | only make guesses Hard Mode allows |
| `--max N` | plan to finish within N guesses (3–6, default 6); see below for how often it can't |
| `--target N` | aim to finish on guess N (2–6) |
| `--sloppy P` | chance of a human slip per guess with guesses to spare (default 0.2, 0 = never) |
| `--seed N` | make random choices reproducible |
| `--copy` | copy the share grid to the clipboard |

Save a default with `wordle-solver settings set max 5`; `wordle-solver help
settings` lists every key.

In `assist`, press Enter on an empty line to play the suggestion. With
`--manual`, enter the colours the website showed as `g`/`y`/`b` (or
`2`/`1`/`0`), for example `bygbb`.

## Evaluating models

Language models can play against the engine and the entropy strategy:

```sh
wordle-solver providers                                  # built-in and saved servers
wordle-solver models ollama
wordle-solver eval --model ollama/llama3.2 --games 10 --seed 42
wordle-solver eval --model omlx/clef-flash-4bit          # a decision model, detected automatically
```

Each run writes a transcript to the `evals` folder beside your saved data
unless you pass `--out`. See [evaluating models](docs/eval.md) for configuration,
held-out answers, transcripts and rerouting.

## Answer data

The benchmark and `play` need no network access: the answer list ships
with the code. Commands that solve a dated puzzle (`wordle-solver`, `-date`,
`-id`, `-from`, `sync`) look the answer up in the publicly available
daily-puzzle data (`https://www.nytimes.com/svc/wordle/v2/YYYY-MM-DD.json`),
using your local date. **The answer is used only to score guesses.** The
solver still plays from the colours alone, and the output says so.

Fetched answers are cached. Answers added after the original list, such as
MOXIE, join the solver's word list, so they are ordinary candidates. Each
game and the player profile are saved, and rerunning a day shows the saved
game (`-fresh` replays it, `-dry` saves nothing). `stats` summarises the
saved games exactly as they were played. The data lives in `wordle-solver`
in your user config folder (`~/Library/Application Support` on macOS,
`~/.config` on Linux, `%AppData%` on Windows); set `WORDLE_SOLVER_HOME` or
pass `-home DIR` to move it, and `clean` deletes only the files the solver
wrote.

## Human-like play

`play`, `sim`, the daily commands and plain `bench` use a model of how a
person plays rather than the strategies above: familiar words, a pair of
favourite openers, occasional slips such as reusing a ruled-out letter, and
a finishing turn drawn from rough human weights. The
[human model](docs/human-model.md) states every assumption and compares the
model with 2022 results people reported: it averages about 4.3 guesses
against their 4.1, and its results are more tightly bunched. Under
`-max` below 6 or `-hard` it drops the slips and pacing and plays carefully.

Over every answer, with `wordle-solver bench [option] --seed N` for seeds
1, 2 and 3 (ranges across the three seeds):

| Option | Mean guesses when solved | Over the limit or lost |
| --- | ---: | --- |
| none | 4.29–4.32 | none |
| `-max 5` | 3.91–3.94 | none |
| `-max 4` | 3.70 | 51–63 games (2.2–2.7%) take 5 or 6 guesses; none lost |
| `-hard` | 3.81–3.88 | 6–8 games lost (0.3%) |

## Development

```sh
gofmt -l .        # prints nothing
go vet ./...
go test ./...     # about 35 seconds: plays every answer
```

CI runs these on Linux, macOS and Windows and cross-compiles every release
archive. Releases are versioned by
[release-please](https://github.com/googleapis/release-please) from
[Conventional Commits](https://www.conventionalcommits.org); merging its
release PR tags a version and attaches binaries.

| Path | What it holds |
| --- | --- |
| `internal/wordle` | Scoring, the strategies and benchmark, and the human-like model |
| `internal/player` | Saved profile, games, answer cache and statistics |
| `internal/selfupdate` | `update`: download, checksum check and binary swap |
| `cmd/wordle-solver` | The command-line tool |
| `tools/report` | Reruns the benchmark; regenerates docs/analysis.md, its charts and the table above |
| `tools/humanref` | Compares the human-like model with reported results (docs/human-model.md) |
| `scripts/build-release.sh` | Builds the release archives |
